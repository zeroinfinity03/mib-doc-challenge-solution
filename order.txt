SOLUTION-NEW — THE WORKING SOLUTION
===================================
Self-contained: its own pyproject.toml and .venv, nothing borrowed from
../solution. Paddle is gone entirely -- RapidOCR won every field, so the
dependency tree is now rapidocr + onnxruntime + pymupdf + numpy + opencv.
That kills the linux-aarch64 problem that forced --platform=linux/amd64.

Rules of the sandbox:
  - ../solution is the SUBMITTED baseline (123.72). It is never edited here.
  - One experiment = one change = one full-corpus measurement vs baseline.
  - A step variant keeps its step number: a step-2 variant is step2_<name>.py.
  - Winners replace the main step file; losers go to the Trash with their
    numbers written down in the scoreboard below.
  - Nothing is deleted. Superseded work moves to ~/.Trash.

SETUP
  uv venv .venv --python 3.12
  uv pip install --python .venv/bin/python -r pyproject.toml

PIPELINE
  step1_scan_hidden.py -> hidden-output/       hidden/injected text, never a value
  step2_ocr.py         -> ocr-output/          RapidOCR PP-OCRv6 small (ONNX)
  step3_filter.py      -> clean-output/        which OCR lines sit on injections
  step4_extract.py     -> parsed/              the ten fields, with provenance
  step5_decide.py      -> predictions.jsonl    adjudication + confidence

  step5_resolver.py    -> (not wired in) the hedge-resolver experiment, kept
                          for its measurements; see exp 7 below.

  eval:
    .venv/bin/python ../mib-doc-challenge/scripts/evaluate.py \
      --truth ../mib-doc-challenge/data/train_labels.csv \
      --submission predictions.jsonl

WHERE OUR REMAINING POINTS ARE (measured on the 124.00 run)
  Classification is 64.43/80; theirs is 71.93. The whole gap is hedging:
  we answer NEEDS_REVIEW on 421 cases, and only 239 of them are truly
  NEEDS_REVIEW. 118 are really APPROVED (7.08 pts forgone) and 64 are
  really DENIED (3.84). Perfect resolution of every hedge would be worth
  10.92 points; that is the ceiling.

  Per-reason EV of a BLANKET flip (why a blunt fix cannot work):
    reason              APPR  DEN  REV   ->APPROVED   ->DENIED
    adjudicator_note       0    0  114      -7.98      -7.98   perfect already
    missing_fee           54   22   32      -0.32      -4.16   richest, mixed
    review_flag            0    4   37      -2.83      -2.35
    med3_no_biometric     21    8    6      +0.36      -1.20
    no_identity_docs      14   11    6      -0.24      -0.60
    redacted_evidence     15    7    9      -0.15      -1.11
    fee_unknown            0    2   28      -2.08      -1.84
  Blanket flips total only +0.53, all of it in three tiny buckets. So the
  competitor's +5.89 cannot be blanket flipping -- it is a trained model
  choosing WHICH cases inside one mixed bucket to resolve. missing_fee is
  the obvious target: 108 cases, half of them truly APPROVED.
  Note our earlier broad ML gate lost 2.85 because it replaced good rules
  everywhere; inside a hedge bucket the floor is +2, so a model can only
  add. That is the structural difference.
